# ViewWeave Bridge

[Japanese lifecycle guide](https://github.com/zabaglione/ViewWeave/blob/main/docs/ja/bridge-output-lifecycle.md)

ViewWeave is an independently developed, unofficial Unity SDK for Looking Glass displays. It is not an official Looking Glass Factory product.

This source package submits completed quilts to an installed Looking Glass Bridge runtime. It does not include Bridge binaries, proprietary headers, or runtime assets. End users should install the self-contained URP or HDRP Git distribution package. Do not install this source package alongside a distribution package because both contain the same runtime assemblies.

## Supported output

Regular Bridge Worker output is supported in Windows D3D11 and D3D12 Unity Editor Play and Windows Player. The `ViewWeaveRig` Editor preview is a separate Edit Mode authoring route. `Pause Preview` drains work and hides the device window while retaining that preview's producer, Unity textures, and output lease; `Resume Preview` continues the same lease. `Close Preview` requests lease return. Native first reports that it no longer references the old source textures; managed then waits for Core/transfer and producer GPU completion, retires those textures, and sends an ACK. Native permits the next generation only after that ACK. The process-level SDK endpoint stays hidden and parked between owners; only process shutdown releases it. Play and Edit Mode device preview take turns owning that endpoint. See [Bridge output lifecycle](https://github.com/zabaglione/ViewWeave/blob/main/docs/bridge-output-lifecycle.md) for the flow and quality behavior.

The source candidate adds a typed lease submission result. `Accepted` means a draw token entered the Native queue, not that a frame reached the display. `Busy` is reserved for a valid Ready lease when the three-token queue is full; it does not AddRef the source texture or allocate a draw payload. Edit Preview retries while retaining its current owner and generation; playback skips only that frame. Invalid, stale, and Native-fault outcomes remain failures. Native submitted/completed/dropped counters are diagnostics, not GPU release or presentation proofs. This corrects a known fatal Busy policy path in the candidate source; it has not been device-tested in the currently installed samples and does not establish that black/delayed handoffs are fixed.

The dated URP device evidence and its limits are summarized in [Bridge output lifecycle](https://github.com/zabaglione/ViewWeave/blob/main/docs/bridge-output-lifecycle.md). Reverse Play-to-Edit remains unresolved. Native tests use fake/WARP resources and do not load the official Bridge SDK or verify device presentation. See [Graphics backends](https://github.com/zabaglione/ViewWeave/blob/main/docs/graphics-backends.md) and the [Japanese lifecycle guide](https://github.com/zabaglione/ViewWeave/blob/main/docs/ja/bridge-output-lifecycle.md) for the support boundary. Vulkan and macOS output are outside the support boundary. Install and run the Looking Glass Bridge runtime separately and connect a display.

The supported entry point is `ViewWeaveBridgeSession` with `ViewWeaveRig` and `BridgeWorkerQuiltOutput` on the same rig. Use `GameObject > ViewWeave > Bridge Rig` to create a ready-to-run rig. Standard scene objects such as Cube and Box render with their existing pipeline materials and lights; they do not need ViewWeave components or sample generators. The menu copies the MainCamera framing and uses the selected Renderer center to set zero-parallax distance when available.

The Bridge Worker follows the Unity Editor's active D3D11 or D3D12 graphics API. Check `SystemInfo.graphicsDeviceType` to confirm it. For D3D12, the worker shares the Unity-rendered Quilt with a D3D11 device on the same GPU adapter and sends it to the official Bridge runtime without CPU image readback. No separate SDK demo project is needed.

The optional Windows URP Lit and Windows HDRP Lit examples are declared as Package Manager Samples. They are copied under `Samples~` and enter the project Assets only after the user explicitly imports them.

`ViewWeaveBridgeSession` exposes `StartSession()`, `StopSession()`, `SetQuality(QuiltQualityPreset)`, `State`, `Quality`, `Profile`, and ASCII `LastError`. The default quality is `Balanced`. The Bridge runtime is located from an explicit absolute `runtimePath`, the `LKG_BRIDGE_PATH` environment variable, or Windows Bridge uninstall registry entries.

The legacy Direct route is separate from `ViewWeaveBridgeSession` and remains D3D11-only. It requires the validated single-threaded Direct3D11 configuration, including `-force-gfx-direct` and `runInBackground=true`.
