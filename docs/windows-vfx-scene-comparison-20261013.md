# Windows URP/HDRP VFX Learning Templates comparison (2026-10-13)

This report compares the saved URP and HDRP Visual Effect Graph 17.6 Learning Templates scenes, inventories their compiled CPU-side graph descriptors, and records isolated Windows Editor rendering checks. It investigates the reported URP Preview-to-Play memory exception. It did not reproduce that incident or establish a single cause.

## Finding

The saved projects use the same Unity 6000.6.4f1 and VFX Graph/SRP 17.6.0 packages; all 32 corresponding VFX graph files have matching SHA-256 values. Their render configurations differ materially: the URP scene is Isolated + Full and resolves to 48 quilt views, with a reference camera saving TAA and post-processing on. The HDRP scene is Isolated + Quarter and resolves to 12 views; it has no saved reference camera and uses AA None. Both pipelines contain VFX per-camera resources, so HDRP does not avoid that class of work. The different view counts, post-processing, AA histories, and pipeline camera submission paths make the saved scenes unequal runtime workloads. They do not imply a fourfold total-memory ratio.

The 32-graph CPU descriptor inventory compiled all graphs successfully in each pipeline. It exposes per-camera temporary resources, but descriptor `size` fields are not a verified native-byte allocation contract. The reported aggregates below sum `size * frameCount` over unique per-camera temporary descriptors (two-frame resources); they exclude ordinary GPU descriptors, including per-camera indirect/sorting resources. A shared-attribute mapping in `PerCameraUpdate` also means that shared inputs must not all be multiplied by view count. The inventory neither measures live GPU allocation nor proves that every graph was active in the incident. In particular, `SampleSDF.vfx` saves `generateMotionVector=true` and an opaque URP output, but its output hierarchy does not implement motion vectors; compiled `hasMotionVector` is false and the inventory has no motion-vector descriptor for it. The authoring toggle alone is not evidence of an active motion buffer.

Small original-scene pilot cases rendered the selected `CollisionSimple` graph in both pipelines. URP passed one-view AA-off, eight-view AA-off, and eight-view TAA/post-processing cases; HDRP passed one-view AA-off. A separate URP `CollisionAdvanced` pilot (capacity 162,000) passed one-view TAA/post-processing after raising a test-only observed-growth stop threshold from 512 MiB to 1 GiB. That is a bounded fixture result, not a measurement of physical VRAM, a full 48-view result, or a reproduction of the reported 54,473 MB. The proposed Custom-instancing comparison was not run: the graph's compiled output is `VFXStaticMeshOutput`, and VFX Graph 17.6 disables the instancing-mode control for that output. The saved Auto/capacity values do not prove an effective batch limit. No A/B, 64x native-allocation, or asset-edit result is claimed.

## Test setup and scope

Source scenes were read from `E:/URPSample_6.6.41f1` and `E:/My project (34)`. Their source projects were not opened or modified. Tests ran in separate repository-local project clones on Windows with Unity 6000.6.4f1, Direct3D 11, and matching VFX Graph/SRP 17.6.0 packages. Looking Glass Bridge was not used or controlled, and no device output was involved. The prepared clone retained the scene camera/ViewRig relationship, disabled other sample effects, then selected the exact original `CollisionSimple` or `CollisionAdvanced` graph. A known inactive unresolved `VFXG_Decal_Eyes` sample reference prevented the whole-scene reference gate from passing; the selected-graph pilot is a separate sanitized fixture and does not certify the complete sample scene.

The pilot kept the normal parent camera and its 128x96 target in addition to the one- or eight-view quilt history cameras, and set `viewCone=0`. The multi-view checks therefore exercised per-view history scheduling and resource lifecycle with coincident camera views; they did not test disparity, parallax, or optical quilt quality. It checked actual quilt scheduler revisions, visible pixel differences against renderer-off controls, temporal-history advancement where TAA was enabled, resource cleanup, and process/graphics counter stop conditions. These cases are bounded Editor tests; they are not Player, Bridge/device, optical, 48-view, all-32-effects-at-once, or long-duration verification.

The fixture's 4096 MB history resource budget compares a process-global graphics-driver counter peak from its baseline around rendering work; it is not a hard preallocation limit on all GPU memory. The associated texture estimate counts all created `RenderTexture` objects, not only VFX-owned or anticipated quilt textures, so the counters have different scopes. The reported error's `graphics growth 54473 MB`, `estimated texture growth 46 MB`, and `budget 4096 MB` remain user-reported values: their original counter baseline, physical RAM/VRAM peak, effective view count, active graphs, and exact runtime settings were not captured here. The present tests neither reproduce those values nor establish that the budget exception caused the Editor crash.

The CPU inventory summarizes graph descriptors and mappings only. It recorded unique per-camera temporary descriptor aggregates of 30,557,288 for URP and 14,015,048 for HDRP, calculated as `size * frameCount` for the two-frame descriptors. Their units, native duplication, lifetime, visibility, and allocation timing are unverified; do not read these aggregates as bytes or multiply them by camera count to infer actual allocation. Ordinary GPU descriptors also include per-camera indirect/sorting resources, and shared attribute inputs are not all replicated per camera. `CollisionAdvanced` contains both a particle output with a temporary motion-vector descriptor and a separate compiled static-mesh output; the static-mesh output disables the instancing-mode control. The source contains per-camera VFX resources in both pipelines; the active graph set and native memory behavior must be measured in the relevant runtime workload before attributing the incident to them.

## Interpretation

Per-camera VFX buffers are a plausible contributor when a graph renders through many quilt cameras, especially alongside URP's saved 48-view Full configuration and TAA/post-processing. This comparison confirms that relevant per-camera descriptors exist in both URP and HDRP, but does not establish that VFX alone caused the large allocation or crash. The saved HDRP scene's 12-view Quarter / AA None configuration and a user-reported HDRP display are not equivalent tests of URP's 48-view TAA workload. Conversely, the small URP passes do not establish safe operation of the full scene at 48 views.

The isolated 1-view `CollisionAdvanced` pass shows that this selected high-capacity graph can complete a short Editor pilot under the 1 GiB fixture stop threshold. It does not validate all output types, the complete sample scene, or the user's Preview-to-Play transition. The Custom-instancing A/B could not answer whether batch configuration would reduce memory because the graph disables that option at compile/UI level.
