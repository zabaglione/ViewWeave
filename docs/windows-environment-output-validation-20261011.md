Other validation-process overlap and residual Bridge/SDK service state were not established. The stack resembles a previously investigated stdout/shutdown fault family, but that similarity does not establish that Bridge caused this incident; see the [separate stdout investigation](windows-stdout-crash-20261011.md) for its distinct measurements. The current shim's first-load standard-handle snapshot/restore protection does not by itself establish the state during this incident. This observation does not change the selected fixture result or establish a general Editor shutdown failure. No Unity reproduction was run.
