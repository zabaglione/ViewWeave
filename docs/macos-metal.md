# macOS Metal output

[User Guide](user-guide.md) · [Technical Guide](technical-guide.md)

## User setup and operation

Use Unity **6000.6.4f1**, URP or HDRP **17.6**, an Apple Silicon Mac, and an installed Looking Glass Bridge runtime. The bundled arm64 plugin requires **macOS 26.0 or later**. ViewWeave uses a dedicated calibration-driven Metal output path. Connect the display as an unrotated, native-resolution extended desktop and run Bridge. Model identifiers are not used as an allowlist, but this does not establish support for every device. Consult [Compatibility](compatibility.md) and the [current calibration validation record](macos-metal-subpixel-validation-20261011.md) for tested scope and limits.

Select the scene camera and choose **GameObject > ViewWeave > Bridge Rig**. On macOS this creates a `BridgeMetalQuiltOutput` backend. Configure the rig through the **ViewWeave Rig** component: **Rendering > Output Quality** selects Preview, Balanced, or Native; **Bridge** provides startup, runtime path, application name, display ordinal, output status, and Start/Stop controls. Enter Play mode to start output. Stop output and wait for GPU retirement before changing quality or transport, then start it again. A blank runtime path discovers the newest installed Bridge in `/Applications` or `~/Applications`. An explicit dylib, its directory, or the Bridge `.app` and `LKG_BRIDGE_PATH` are also accepted.

Camera, reference camera, focus, orbit, physical framing, Quilt Capture, and Video Export use the shared Rig frontend. While connected in Play mode, **Use Connected Display Size** copies the validated physical calibration into the aperture fields without enabling physical framing automatically. Physical 1:1 framing requires the aperture aspect to match the display. Stopping Metal output cancels an active or paused recording on that renderer before restoring its local configuration. The Metal component's Inspector is for technical diagnostics.

In Edit Mode, open **Preview** on ViewWeave Rig and choose **Start Local Edit Mode Preview** or **Start Looking Glass Device Preview**. Local preview uses the Rig's local Quilt profile; device preview uses Bridge's validated display profile and **Output Quality**. **Pause Preview** holds the last image, **Resume Preview** reuses the producer, and **Close Preview** stops it. Close and wait for GPU retirement before changing quality or transport. A private producer preserves the source Rig and camera settings. Entering Play, reloading scripts, closing its Authoring window, or changing the window's Rig stops preview.

For saved Quilts, enter Play and start Metal output, then choose **Capture & Playback > Playback**. Select a full Quilt PNG or completed PNG recording folder, validate it, and use Play / Pause / Resume / Stop. Its dimensions, grid, aspect, and available camera geometry must match the active output. Playback pauses normal Quilt rendering; normal Stop or sequence completion restores it only while the same output and Rig configuration remain valid. Output Stop, Play exit, and script reload invalidate playback and retain GPU resources until retirement proof completes. The scene stores the attached backend: moving a scene between macOS and Windows does not automatically replace its output component.

Support is determined from Bridge metadata, not a model identifier. Bridge supplies display and Quilt geometry, aspect, viewcone, DPI, and raw `center`/`pitch`/`slope` calibration; `get_ri_for_display` and `get_bi_for_display` provide the channel indices for standard RGB/BGR order. The Metal path accepts `CellPatternMode` 0–4. A table requires at least one cell for mode 0, two for modes 1, 2, and 4, or four for mode 3, and can contain at most four cells. A tableless profile is supported only for mode 0. When a table is present, the JSON mode must be supplied as `CellPatternMode` or `cellPatternMode`; a missing mode or a count below the mode minimum or above four is rejected. Tableless mode 0 supports RGB/BGR with `flipX` and `invertedViews` each set to 0 or 1; profiles with cells require `invertedViews=1`. For a tableless profile, `flipX=1` mirrors image X and reverses tilt and RGB direction. With a cell table, `flipX=1` reverses tilt only, without mirroring display UVs or reordering RGB offset X values. Cell offsets remain raw per-channel X/Y pixel values. Reading a cell table additionally requires the local Bridge HTTP JSON route at `127.0.0.1:33334`; tableless mode 0 uses the native SDK only. Unknown modes, malformed tables, non-finite values, or a mismatch with the native calibration are rejected. `fringe` must be finite but is not used for optical correction. The display must be unrotated, at native resolution, and extended. See the [Bridge subpixel calibration note](bridge-subpixel-calibration.md) for mode index rules and metadata retrieval. Choose Preview, Balanced, or Native before starting. The full Bridge-reported Quilt grid is retained at every quality level; rendering a large view count can be expensive, so start with Preview.

## Subpixel processing

Choose **Subpixel Processing** in the ViewWeave Rig Inspector after stopping output/device preview and waiting for GPU retirement. **Automatic** uses the Bridge calibration and its cell table when present. **ClassicRgb** explicitly selects evenly spaced RGB sampling using the optical calibration, for diagnostics. **CalibratedCells** requires a Bridge cell table and rejects a tableless display such as Go. Pattern mode and XY offsets always come from Bridge.

The `BridgeSubpixelMode` contract is shared by Windows and macOS. Windows can retain the same Inspector setting, but its current Bridge-managed output accepts only Automatic. Manual choices fail before starting a session; Windows manual application and special-cell physical output remain unverified.

## Implementation and verification notes

Current validation passed Native CTest 7/7 and three v3 connection/cancellation cycles. Built-in Linear and Gamma GPU comparisons each passed 28 cases over 64,512 samples, with maximum errors 0.001956 and 0.001961; URP and HDRP Linear GPU comparisons each passed 28 cases. The current URP and HDRP Editor flows checked Preview and Play, PNG capture, silent recording and playback, and Stop/Restart. The four Go Player fixtures (URP/HDRP, Development/Release) also passed image, configuration rejection, cleanup and natural-exit gates. These checks do not establish general physical optical support; 16-inch Spatial Landscape output remains untested. Audio recording is not supported on macOS. See the [current calibration validation record](macos-metal-subpixel-validation-20261011.md) for the complete scope and limits.

## Native plugin build

Run `python3 tools/build_macos_plugin.py --headers /absolute/path/to/public/UnityPluginAPI/headers` with public Unity NativeRenderingPlugin headers. Without `--headers`, the tool obtains pinned upstream headers into its ignored build directory. It builds the repository-owned shim, runs native CTests, and installs the dylib/importer metadata and provenance to the Bridge package. The current output path uses `open_v3` with a 180-byte `LkgMetalDisplayInfoV3` and carries up to four raw RGB XY cells, each 24 bytes. The dylib is replaced atomically to avoid stale macOS code-signing pages; restart Unity after updating it to load the new native version. `--universal` also compiles the Intel slice; Intel runtime execution is not implied by a successful build. Official Bridge libraries and headers are never bundled. ViewWeave independently implements the mathematical mode rules after checking their meaning against official Looking Glass Unity Plugin 3.2.8; no vendor code is ported or bundled. Run `python3 tools/build_upm_distribution.py` after changing the source package to regenerate both self-contained distributions.

The verification project is `Tests/Metal/Unity`. `MacOSMetalValidationBuilder.Build` creates `.local/macos-validation/ViewWeaveMetal.app`; `Prepare` creates its Editor scene. The application rotates its sample geometry and records frame counters. R stops/restarts output, and Escape stops and exits. Generated scenes, Players, and detailed logs are verification artifacts rather than package content.

## Rendering and lifetime

Bridge supplies metadata and calibration, then its SDK is uninitialized. The display window and optical sampling are owned by ViewWeave. Unity renders/interlaces on Metal; a Unity render event copies the result into one private Metal texture. Unity producer completion schedules the presentation queue. Completion of ViewWeave's own consumer command buffer permits the next copy. Busy frames are dropped; no image is read back to the CPU during streaming. Teardown uses a one-pixel queue-tail readback to prove Unity completion before releasing the texture, together with native completion.

Stop immediately closes admission and hides the window. GPU retirement can continue afterward; `IsClosing` distinguishes this from full retirement. A new session waits for the previous session to retire. Pending event data and GPU callbacks retain their own session and textures. AppKit objects are released on the main thread. Screen disconnect, movement, or resolution changes stop output rather than continuing with stale pixel placement. Reconnect and start again after restoring the display arrangement.

The Windows `ViewWeaveBridgeSession` and D3D Worker remain Windows-specific. Metal preview and playback use dedicated controllers with shared Rig UI, source validation, and Editor producer/resource utilities. Shared, Metal and Windows responsibilities are described in [Platform boundaries](bridge-platform-architecture.md). The earlier finite `BridgeMetalExperimentalOutput` remains a separate diagnostic route. It must not share a process with this output after beginning its experiment; restart Unity between routes.

## Editor assertion when stopping Play

`Mismatched state in DefaultScenario, was Stopping but expected Idle` is a known Unity issue when script changes made during Play are recompiled on stopping. [UUM-154172](https://issuetracker.unity.com/issues/25291/mismatch-state-in-defaultscenario-error-is-thrown-when-exiting-play-mode-with-a-modified-script-and-recompile-after-finished-playing-enabled) lists 6000.6.4f1 as affected. Stop Play before changing source, then wait for imports and compilation to finish before starting again.

Unity's documented workaround is Unity Settings > General > Script Changes While Playing > `Recompile And Continue Playing`. This Editor preference affects other projects and allows recompilation during Play; change it only if that behavior is desired.

## Optical calculation and provenance

The interlace shader is an original implementation, not an import or port of the HoloPlay shader. It computes the lenticular phase for each RGB subpixel, selects a Quilt view, and samples that view. For a tableless mode-0 profile, `flipX=1` mirrors image X and reverses tilt and RGB direction. For a profile with cells, `flipX=1` reverses tilt only; it does not mirror display UVs or reorder RGB offset X values. RGB/BGR channel indices select the corresponding phase. `fringe` is only checked for finiteness and does not participate in correction. The calibration conversion follows the mathematical relationship in the Apache-2.0 [official WebXR configuration](https://github.com/Looking-Glass/looking-glass-webxr/blob/b44ed27fea197f28fbe4cb669bc350d141a9f8b1/src/LookingGlassConfig.ts); current mode and cell rules are documented in the [Bridge subpixel calibration note](bridge-subpixel-calibration.md):

`shaderPitch = rawPitch × screenWidth / dpi × cos(atan(1 / rawSlope))`

`tilt = screenHeight / (screenWidth × rawSlope)`; `RGB step = 1 / (3 × screenWidth)`.

The [Bridge native reference](https://lfdocs.lookingglassfactory.com/software/looking-glass-bridge-sdk/native-function-reference) and the installed runtime's public declarations provide the metadata ABI. Unity's [public native Metal interface](https://github.com/Unity-Technologies/NativeRenderingPlugin/blob/522254181faf188efa8b50c3e3bf6fce720b26e4/PluginSource/source/Unity/IUnityGraphicsMetal.h) supplies the producer command buffer. GPU/unit/build proof, screen capture, and physical optical acceptance are different evidence; see the [current calibration validation record](macos-metal-subpixel-validation-20261011.md) for the verified scope and limits.
