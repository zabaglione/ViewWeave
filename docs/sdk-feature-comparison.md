# Comparison with Official Features

This table summarizes features described in Looking Glass Factory's official materials and the implementation status of ViewWeave for users. ViewWeave is an independent, unofficial SDK and does not guarantee source or complete feature compatibility with the official SDK. For details, see [Official SDK Feature Research](official-sdk-feature-research.md); for feature procedures, see [Quilt Capture](quilt-capture.md) and [Camera Framing](quilt-authoring.md).

| Feature | Confirmed in official material | ViewWeave status |
| --- | --- | --- |
| Quilt rendering and assembly | Hologram Camera outputs multiview images as a Quilt. | A dedicated Camera renders each view individually, assembles Quilt tiles on the GPU, and sends them to Bridge. Standard Cubes/Renderers need no per-object scripts. The current path uses 48 StandardRequest calls; it does not share rendering across views or use depth interpolation. |
| Device profile and optical calibration | Official SDK uses device profile/calibration data. | Receives profile data such as display dimensions, view cone, Quilt dimensions, and grid from Bridge. Does not provide UI to edit Factory optical calibration or an independent correction system. Profile handling for arbitrary devices and optical quality are unverified. |
| Save still Quilt images | `QuiltCapture` API can save a Quilt PNG and a 2D center-view image. | Saves Quilt PNG, JSON sidecar, and center-view PNG. Existing D3D11 URP/HDRP suites passed 2/2 each. The current DX12 fake-output suites passed 1/1 per URP/HDRP. Bridge capture and physical display remain unverified. |
| Record video and image sequences | Official material describes manual video recording, time ranges, VideoPlayer synchronization, Pause/Resume, Take, codec, and metadata. It also explains creating H.264 from Quilt images. | Implements PNG sequences/Pause-Resume and silent MP4 post-processing. An end-to-end test passed 1/1 exporting three frames from an actual URP DX12 Recorder output to 30 fps H.264/yuv420p (256x192, 4x2/8 views; no Native/Bridge). This is separate from the synthetic 48-view CPU smoke. Manual Editor-window operation is unverified. Audio integration is limited to probes; Timeline/VideoPlayer synchronization is unimplemented. |

Static review and DX12 RunCameraAuthoring passed. Interactive Scene GUI dragging is unmeasured. Editing the Camera during Play is out of scope. |

Core Quilt playback and DX12 CPU smoke passed. D3D11 and D3D12 device fixtures passed URP/HDRP Start/Stop/Restart at a 3840x2160 display profile and 7680x4320, 8x6/48-view Quilt, with one submission/completion for each Start and Restart and zero native/retention pending after Stop. ### Validation Status for Capture and Camera Adjustment

D3D11 URP/HDRP PlayMode smoke tests on Unity 6000.6.4f1 passed 2/2 each. DX12 fake-output Core smoke and one URP/HDRP capture test each passed 1/1. Separately, the actual URP DX12 Recorder-to-silent-MP4 E2E passed 1/1. Validation baseline 4230c4c included PR #4 and CI passed. Camera authoring/playback/Mono audio were added in the current change. The six audio fake cases and eight actual/silent cases passed individually after a focused rerun; all 12 Playback safety scenarios also passed individually. An isolated DX12 official Bridge fixture passed the body gate for holding a pre-generated 7680x4320/8x6 PNG, Pause/Resume, and a three-image, 1 fps sequence, with one Start/Stop each and pending 0. However, Unity Editor exited with an access violation at Unity.dll offset `0x44383df` (exit code `-1073741819`), so normal natural exit was not accepted. This does not demonstrate live 48-camera rendering or physical display. A limited Editor reload probe covered retention of the serialized playback recovery record and RenderTexture reference, post-reload fence/readback, and test-only handoff only.

Pixel checks such as PNG orientation and intermediate colors used a diagnostic pattern blitted to a RenderTexture after running URP/HDRP. The current D3D12 Bridge fixture played a pre-generated PNG; it does not demonstrate capture saving, rendering all 48 cameras in a real scene, or optical quality. Direct gizmo manipulation in the Scene view, saving a Quilt while sending to official Bridge, and physical display remain unverified. Details: [Quilt Capture](quilt-capture.md), [Camera Framing](quilt-authoring.md), and [HDRP Performance Record](resumed-hdrp-vfx-performance.md).

Research date: 2026-10-08 (additional validation evidence captured on 2026-10-07 UTC).

### Validation Boundary as of 2026-10-07

Central 2D capture and Recorder Pause/Resume passed scoped DX12 fake-output URP/HDRP tests; they do not establish Bridge output. Silent MP4 export passed its fake-process suite and a real FFmpeg/ffprobe 7.0.2 CPU-only synthetic smoke. Separately, an actual URP DX12 recording-to-export test passed 1/1 for three 256x192 4x2/8-view frames at 30 fps, H.264/yuv420p, without Native or Bridge. This does not establish physical output or manual Editor-window interaction. The UI recommends the official Studio filename tag. Camera authoring passed its targeted DX12 test; playback Core CPU smoke passed, while Bridge/Native playback remains untested. See [capture guide](quilt-capture.md), [video export](quilt-video-export.md), and [remaining-work validation](benchmarks/remaining-work-validation-20261007.md).
