# URP camera-owned VolumeStack reuse experiment

> Audience: Unity and rendering developers. This is a dated research or validation record limited to the revision, platform, and conditions stated here; it does not establish support for other configurations. For current support and setup, see [Compatibility](compatibility.md) and [Getting started](getting-started.md). Browse the [Technical guide](technical-guide.md) or [User guide](user-guide.md).

The private experimental branch `codex/urp-volume-reuse` at commit `c1d597e` adds the opt-in `Reuse Camera Owned Volume Stack For Quilt` setting to its URP quilt camera. This experiment is not part of the main package. The URP evaluation project was restored to its previous package pin `044e911940fcba4b2dadfaac65ddd83be5f4f5a4` after the trial. In the trial branch, the adapter temporarily switches a supported camera to URP's `ViaScripting` volume update mode, updates the camera-owned stack once for each quilt view, uses that same stack for the Motion Blur check and URP render, then releases only the stack owned by the active lease and restores the original update mode and VolumeManager stack.

The path is used only while the application is playing, the camera has no existing `UniversalAdditionalCameraData.volumeStack`, and that camera effectively uses automatic per-frame Volume updates. This includes an explicit camera mode of `EveryFrame` and `UsePipelineSettings` when the active URP asset selects `EveryFrame`. Cameras using `ViaScripting`, cameras whose effective pipeline setting is `ViaScripting`, Edit Mode, and cameras that already own a VolumeStack keep the existing validation-stack path.

The optimization does not reduce the number of rendered views, disable effects, freeze Volume profiles, or replace local Volume blending with a global profile. The camera-owned stack is updated at each view position, so local Volumes and animated Volume values remain eligible for evaluation on every view.

There is one callback timing constraint: the adapter updates the stack immediately before issuing a view render request. A `RenderPipelineManager.beginCameraRendering` callback that changes this camera's Volume trigger, Volume layer mask, or Volume configuration runs after that update and may be too late to affect the current quilt view. Keep the setting disabled if a project depends on such callback-time changes. Changes made before the quilt render begins remain in the normal update path.

This is a performance experiment in the private trial branch, and its result does not confirm a performance improvement. The main-branch `Start` and `StartGate` runs retain their original six phases; `UrpSamplePerformanceHarness.StartVolumeStackComparison(outputDirectory, cameraDistance)` exists only in the trial harness. It runs a dedicated A/B/A sequence with 48 views in every phase: reuse off, reuse on, then reuse off again. The existing camera, simulation, time, render-count, and scene guards still apply. The B phase is only accepted as verified when all 120 measured frames have matching begin/end camera callbacks, the same camera-owned stack, ViaScripting mode, and an active lease. A shorter verified count is written as a failed run and must not be reported as a successful comparison.

At trial commit `c1d597e`, the graphics compatibility suite passed 7/7 PlayMode tests in 17.81 seconds with Unity 6000.6.4f1, URP 17.6.0, and DX12. The cases observe camera-owned stack identity at all eight test view callbacks, verify that URP uses it, cover `UsePipelineSettings` resolving to `EveryFrame`, exercise fallback when the camera uses `ViaScripting` or already owns a stack, and verify state restoration when Motion Blur rejects a view. A local-volume fixture crosses a blend boundary across quilt views, compares per-view Bloom values with the setting off and on, then changes the profile and checks that the next quilt refreshes each view. These test passes establish behavior, not performance.

## Pipeline-change abort validation

The seventh case, `CameraOwnedVolumeStackLeaseAbortsWhenPipelineAssetChangesDuringFinalView`, covers an active render-pipeline asset change on the final view: the incomplete quilt does not advance its completion revision or emit a completion notification, the lease releases only its owned stack, and a replacement stack installed in the camera slot by the pipeline change remains untouched for the next stable quilt.

An earlier fixture initialization failure at 871 is separate from this completed 7-test run. The session showed 81 missing-script GUI warnings; the Garden missing-script census was 0 and the fresh error count was 0. These observations are limited to this test session and census. The separate Garden A/B/A measurement is recorded in [the performance evaluation](urp-sample-performance.md#garden-volumestack-reuse-aba-trial) and [its compact summary](benchmarks/urp-volume-stack-garden-20261007.summary.csv); it did not confirm a performance improvement.
