# URP camera-owned VolumeStack reuse experiment

The URP quilt camera has an opt-in setting, `Reuse Camera Owned Volume Stack For Quilt`. It is disabled by default. When enabled, the adapter temporarily switches a supported camera to URP's `ViaScripting` volume update mode, updates the camera-owned stack once for each quilt view, uses that same stack for the Motion Blur check and URP render, then releases the temporary stack and restores the original update mode and VolumeManager stack.

The path is used only while the application is playing, the camera has no existing `UniversalAdditionalCameraData.volumeStack`, and that camera effectively uses automatic per-frame Volume updates. This includes an explicit camera mode of `EveryFrame` and `UsePipelineSettings` when the active URP asset selects `EveryFrame`. Cameras using `ViaScripting`, cameras whose effective pipeline setting is `ViaScripting`, Edit Mode, and cameras that already own a VolumeStack keep the existing validation-stack path.

The optimization does not reduce the number of rendered views, disable effects, freeze Volume profiles, or replace local Volume blending with a global profile. The camera-owned stack is updated at each view position, so local Volumes and animated Volume values remain eligible for evaluation on every view.

There is one callback timing constraint: the adapter updates the stack immediately before issuing a view render request. A `RenderPipelineManager.beginCameraRendering` callback that changes this camera's Volume trigger, Volume layer mask, or Volume configuration runs after that update and may be too late to affect the current quilt view. Keep the setting disabled if a project depends on such callback-time changes. Changes made before the quilt render begins remain in the normal update path.

This is a performance experiment, not a measured performance claim. The normal `Start` and `StartGate` runs retain their original six phases. To isolate the optimization, call `UrpSamplePerformanceHarness.StartVolumeStackComparison(outputDirectory, cameraDistance)` in Play Mode. It runs a dedicated A/B/A sequence with 48 views in every phase: reuse off, reuse on, then reuse off again. The existing camera, simulation, time, render-count, and scene guards still apply. The B phase is only accepted as verified when all 120 measured frames have matching begin/end camera callbacks, the same camera-owned stack, ViaScripting mode, and an active lease. A shorter verified count is written as a failed run and must not be reported as a successful comparison.

The graphics compatibility tests observe the camera-owned stack identity at all eight test view callbacks, verify that URP uses it, cover `UsePipelineSettings` resolving to `EveryFrame`, exercise fallback when the camera uses `ViaScripting` or already owns a stack, and verify state restoration when Motion Blur rejects a view. A local-volume fixture crosses a blend boundary across quilt views, compares per-view Bloom values with the setting off and on, then changes the profile and checks that the next quilt refreshes each view.
