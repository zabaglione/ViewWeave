# Compatibility matrix

The supported runtime Session target is Unity 6000.6.4f1 on Windows with URP or HDRP. The Bridge Worker path supports Editor Play and Windows Players on D3D11/D3D12. On D3D12, Unity shares the Quilt with a D3D11 Worker on the same GPU, which sends it to the official Looking Glass Bridge runtime without CPU image readback. Legacy Direct supports D3D11 only. A separate, explicit Edit Mode preview is available from `ViewWeaveRig` on Windows Editor D3D11/D3D12; this does not make regular Sessions available outside Play Mode. URP/HDRP local GPU fixtures confirmed eight-view rendering, layout rebuild, proof-based texture retirement, and Stop/readback with zero pending retention. D3D11 and D3D12 device fixtures passed URP/HDRP Start/Stop/Restart at a 3840x2160 display profile with a 7680x4320, 8x6/48-view Quilt, one submission/completion for each Start and Restart, and zero native/retention pending after Stop. Manual optical appearance review remains pending. One targeted hidden-Editor fixture confirmed cleanup and explicit restart across Domain Reload; see [Graphics backends](graphics-backends.md) for File > Exit results; normal Editor exit remains unverified. There is no regular managed Session display path on macOS. See the matrix below and [Windows validation](windows-validation.md) for tested configurations. Source compatibility with the official API is not guaranteed. macOS Looking Glass Go uses the dedicated `BridgeMetalQuiltOutput` on Apple Silicon, independently of the Windows Session. The package includes an arm64 native shim. Setup and evidence are in [macOS Metal](macos-metal.md). The earlier finite `BridgeMetalExperimentalOutput` remains a separate diagnostic route.

Windows shutdown adds Worker/Legacy D3D11 final drain, a per-Session close ledger, and GPU proof. Local Native full CTest passed 6/6 with both Unity PluginAPI and the pinned header. Editor/Player shutdown fixtures confirmed natural exit after Native/managed completion proof. An earlier full Bridge fixture confirmed natural exit after Native/managed drain with a package containing an automatic WM_CLOSE candidate. In V6, one real Windows D3D12 Editor `File > Exit` request retired an owned texture that was still awaiting GPU proof when the gate began, after completing the required proof inside the gate; the native host then joined, managed ownership reached zero, and the Editor exited naturally with code 0. The historical access-violation cause is unknown; V6 does not prove that it removed the cause. Save/cancel GUI tests remain incomplete, as does manual optical review of the new Edit Mode preview. Its D3D11 and D3D12 URP/HDRP Start/Stop/Restart fixtures are recorded above; a targeted preview Domain Reload cleanup/restart fixture passed, while see [Graphics backends](graphics-backends.md) for File > Exit results; normal Editor exit remains unverified. The regular 48-view optical quality and performance limits are unchanged. See [Shutdown validation](shutdown-validation-20261008.md) and [Graphics backends](graphics-backends.md) for scope, procedures, and limitations.

Quality changes pause transfers, reconfigure resources on the same host/window, and then resume automatic rendering. Explicit `StopSession()`/`StartSession()` is an independent restart path.

In subsequent fixed-condition URP/HDRP Player validation, each of four stages—Preview 1920x1080, Balanced 3840x2160, Native 7680x4320, then Preview—completed 122 times. All tiles were non-empty; movement and parallax were checked; after explicit Stop/Start, 120 draws completed with zero pending work. This is a fixed-condition result, not a guarantee for other devices or optical quality.

An older Windows D3D11 Player validation on a package snapshot checked URP Simple Burst with a regularly controlled Camera at 1/8/48 views and GRD on/off (six conditions). HDRP priming did not pass, with zero normal-image difference. These historical results are limited to specific content and control conditions; they do not establish current D3D12 project integration or general VFX support.

The historical URP driver-targeted 5/5 result was limited to a regularly controlled Camera and experimental driver conditions. The current DX12 cold suite remains 6/7 and preserves the FOV50 Simple Burst `alive=0` failure. Later memory diagnostics 7/7 and a focused filter 3/3 add observations but do not prove a permanent fix or general VFX support.

After the current guard, targeted Core/SRP/VFX Editor tests passed 17/17 in Linear (including six VFX driver tests) and 8/8 for Gamma MSAA/VFX (including one Gamma VFX rejection). This is not an update to the full test matrix and is separate from the older 123-test integration result. Gamma MSAA/regular URP Bridge Player execution is unverified. Gamma VFX is officially unsupported. Evidence: `.local/windows-improvement/bridge/linear-srp-vfx.xml` and `.local/windows-improvement/bridge/gamma-msaa-8-original-threshold.xml`.

In a separate private trial, `codex/urp-volume-reuse`, VolumeStack-change PlayMode tests passed 7/7, but the Garden A/B/A measurement showed no performance improvement, so the change was not adopted.

VFX Graph requires Linear color space. Unity Visual Effect Graph 17.6 officially does not support URP Gamma color space; HDRP also requires Linear. In Gamma, `UrpVfxCameraDriver` stops before creating a Camera or RenderTexture and reports `VFX Graph requires Linear color space; URP Gamma is unsupported`. Gamma VFX rendering is outside supported scope. See [Unity Visual Effect Graph 17.6 system requirements](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.6/manual/System-Requirements.html) and [Unity HDRP asset requirements](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.6/manual/create-an-hdrp-asset.html).

An older Windows D3D11 PlayMode integration on a package snapshot passed 108 of 123 tests, failed 15, and skipped 0: Session 18/18, compatibility 37/37, GRD 27/27, added SRP 10/10, SRP extension 2/2, VFX driver 5/5, and Samples 4/4. The non-passing cases were one HDRP priming test and 14 VFX compatibility tests. A separate contemporaneous VFX matrix passed 5/20 and failed 15/20. Non-passing conditions did not show sufficient effect across all tiles. This history does not indicate the outcome of current D3D12 project integration or all VFX conditions. Bridge-connected URP/HDRP Players were checked under fixed conditions for six combinations of Preview/Balanced/Native and GRD on/off. These are individual fixtures and fixed-condition results, not general feature support or a guarantee on arbitrary devices. Quality-switch cycles also passed under fixed conditions. Performance advantage, manual optical review of all views, distribution signing, hotplug, and multiple devices remain unresolved. Dedicated macOS Go evidence is recorded separately in [macOS Metal](macos-metal.md).

The official 4 beta/alpha materials checked here target URP 17.0–17.1 and Unity 6000.0–6000.1, and do not support official HDRP. Default depth interpolation has transparency limitations, and VFX requires extra settings. Do not treat the official iOS target as excluded by this project; the initial release scope of this SDK is defined separately.

The official 3.x materials primarily target Built-in, have URP limitations, and do not support HDRP. The official 4 beta distribution and alpha materials describe Unity 6000.0.39–6000.1.5, URP 17.0.4–17.1, and Render Graph. Official 4 also does not support HDRP and has limitations in view interpolation and transparency.

Primary sources: [Official Unity Plugin](https://lookingglassfactory.com/software/looking-glass-unity-plugin), [official 3.x documentation](https://lfdocs.lookingglassfactory.com/software/index), [official 4.0 alpha documentation](https://lfdocs.lookingglassfactory.com/software/index/unity-plugin-4.0-alpha).

## DX12 capture and shutdown evidence (2026-10-07)

At the time of these tests, baseline revision `4230c4c` included PR #4 and CI run `37614129521` had passed. This change set passed the Playback safety 12 scenarios individually and the Mono Audio fake 6/6 plus actual/silent 8 cases individually (the latter after a focused test-only correction). The isolated DX12 official Bridge PNG playback fixture passed its static/sequence body checks (3 sequence submissions, 0 skipped, same Ready generation, pending 0), but the Unity process exited with `0xC0000005` in `Unity.dll` at offset `0x44383df`; clean natural Editor exit is not established. The fixture used pre-rendered PNGs and did not exercise live 48-camera rendering. Audio Bridge delivery and production reload/shutdown ordering remain open; a limited test-only Editor reload probe does not prove natural exit. The original cold DX12 VFX driver suite remains 6/7 with FOV50 `alive=0`; separate 7/7 memory diagnostics and a 3/3 focused filter run do not prove a permanent fix. URP and earlier HDRP Editor-stop `0xC0000005` observations remain unresolved and are separate from this isolated fixture event. The Native image guard is preventive and does not establish the vendor-crash cause or fix. These targeted results do not establish physical 48-view quality.
