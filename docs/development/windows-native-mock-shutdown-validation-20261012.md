# Windows Native mock shutdown and stdio regression tests (2026-10-12)

After the isolated Unity EditMode runner failed before producing NUnit results, the existing Windows Native CTest mocks were rebuilt from the repository's current `Native` source and run independently of Unity. The build directory is `Native/build-worker-release-vs`, configured for Visual Studio 2022 x64 Release with `BUILD_TESTING=ON`, `LKG_TRANSPORT_TESTS_ONLY=OFF`, and the installed Unity 6000.6.4f1 PluginAPI headers. Its CMake source directory resolves to `REPO_ROOT/Native` at revision `11312b8c6cf824d9a7ac7c8940e95cee742fa076`; no Native source edits were present. The sandbox build initially could not read Windows SDK registry metadata; the same target build completed with host access.

The first current-source build produced the fake stdio module, shim, loader lifecycle fixture, and shutdown fixture. Its selected Release CTest run passed 4/4 tests in 0.81 seconds. After a read-only audit confirmed the remaining registrations avoid the production Bridge, vendor runtime, physical display output, and GUI services, nine additional current-source test targets were built. A second Release CTest invocation ran the other 15 registered tests, excluding the first four, and passed 15/15 in 16.47 seconds. Across the two distinct runs, all 19 registered Windows CTest cases passed; this was not one unfiltered CTest invocation.

- `lookingglass_stdio_load_guard_test` — verifies standard-handle preservation around a fake static-CRT module and test shim.
- `lookingglass_bridge_loader_lifecycle_test` — exercises fake-runtime load, initialize, unload, and display metadata behavior.
- `lookingglass_bridge_shutdown_contract_test` — checks shutdown ordering and behavior through a fake Bridge runtime and test shim.
- `lookingglass_bridge_shutdown_exception_contract_test` — checks the fake-runtime uninitialize-exception path.

The remaining run covered `lookingglass_worker_common_test`, `lookingglass_metadata_test`, `lookingglass_subpixel_calibration_test`, `lookingglass_metal_calibration_test`, `lookingglass_bridge_subpixel_metadata_test`, `lookingglass_manual_subpixel_presenter_test`, `lookingglass_worker_transport_test`, `lookingglass_worker_cleanup_exception_test`, `lookingglass_worker_host_initialize_failure_test`, `lookingglass_worker_host_uninitialize_failure_test`, `lookingglass_persistent_d3d11_device_test`, `lookingglass_worker_preview_pause_test`, `lookingglass_worker_preview_lease_test`, `lookingglass_bridge_static_present_test`, and `lookingglass_stable_sdk_input_d3d11_test`. These span CPU and synthetic validation, fake Bridge interfaces, loopback-only HTTP, and graphics-oriented fixtures. The test sources contain offscreen WARP/private-D3D12 paths, but the runtime log does not identify which graphics backend was instantiated. Each selected case emitted an explicit pass marker; the log showed no skip, unsupported, or no-device marker. The worker-transport test did not emit its documented skip message for lack of a hardware D3D12 adapter, although the log does not identify the backend used.

These Native tests include CPU checks, fake interfaces, loopback HTTP, and graphics-oriented fixtures. They do not start Looking Glass Bridge, load the vendor Bridge runtime, produce Looking Glass display output, launch Unity, or reproduce the user's Editor crash. They provide narrow evidence for the selected cases and do not identify the crash cause or establish that every production shutdown condition is safe. The runtime graphics backend was not recorded. The Bridge application was not stopped or started. No built DLL was copied into `Distribution`.

The validation JSON records source and executable hashes and each CTest invocation separately. The initial four-test `LastTest.log` and the later 15-test log are archived as ASCII-normalized native-only files at [initial LastTest.txt](../validation/windows-native-mock-shutdown-validation-20261012-LastTest.txt) and [remaining 15 LastTest.txt](../validation/windows-native-mock-shutdown-validation-20261012-LastTest-remaining15.txt), so later CTest runs cannot overwrite the evidence.
