# macOS Metal implementation and validation

For setup and operation, see the [macOS Metal guide](../macos-metal.md).

Support is determined from Bridge metadata, not a model identifier. Bridge supplies display and Quilt geometry, aspect, viewcone, DPI, and raw `center`/`pitch`/`slope` calibration; `get_ri_for_display` and `get_bi_for_display` provide the channel indices for standard RGB/BGR order. The Metal path accepts `CellPatternMode` 0–4. A table requires at least one cell for mode 0, two for modes 1, 2, and 4, or four for mode 3, and can contain at most four cells. A tableless profile is supported only for mode 0. When a table is present, the JSON mode must be supplied as `CellPatternMode` or `cellPatternMode`; a missing mode or a count below the mode minimum or above four is rejected. Tableless mode 0 supports RGB/BGR with `flipX` and `invertedViews` each set to 0 or 1; profiles with cells require `invertedViews=1`. For a tableless profile, `flipX=1` mirrors image X and reverses tilt and RGB direction. With a cell table, `flipX=1` reverses tilt only, without mirroring display UVs or reordering RGB offset X values. Cell offsets remain raw per-channel X/Y pixel values. Reading a cell table additionally requires the local Bridge HTTP JSON route at `127.0.0.1:33334`; tableless mode 0 uses the native SDK only. Unknown modes, malformed tables, non-finite values, or a mismatch with the native calibration are rejected. `fringe` must be finite but is not used for optical correction. The display must be unrotated, at native resolution, and extended. See the [Bridge subpixel calibration note](bridge-subpixel-calibration.md) for mode index rules and metadata retrieval. Choose Preview, Balanced, or Native before starting. The full Bridge-reported Quilt grid is retained at every quality level. At Native quality, the complete tile area determines rendering dimensions; raw Bridge calibration metadata stays intact. This conversion is shared by Windows and macOS; rendering a large view count can be expensive, so start with Preview.

## Implementation and verification notes

The arm64 shim was rebuilt with the common calibration validator, shared sampling shader and Metal API v4. Validation covers Native CTest 8/8, three Go v4 cancellation/restart cycles, synthetic Metal GPU comparisons across UNORM/sRGB, scaling and patterns 0–4, and Go URP/HDRP regression flows. Gamma sRGB requests that Unity converts to UNORM are excluded from successful case counts. Special-cell physical displays, 16 Spatial Landscape, optical quality, Intel execution and audio recording remain unverified. See the [current validation record](macos-unified-subpixel-validation-20261011.md) for counts and Editor/Player scope.

## Native plugin build

Run `python3 tools/build_macos_plugin.py --headers /absolute/path/to/public/UnityPluginAPI/headers` with public Unity NativeRenderingPlugin headers. Without `--headers`, the tool obtains pinned upstream headers into its ignored build directory. It builds the repository-owned shim, runs native CTests, and installs the dylib/importer metadata and provenance to the Bridge package. The current output path uses mode-aware `open_v4` with a 180-byte `LkgMetalDisplayInfoV3` response and carries up to four raw RGB XY cells, each 24 bytes. The dylib is replaced atomically to avoid stale macOS code-signing pages; restart Unity after updating it to load the new native version. `--universal` also compiles the Intel slice; Intel runtime execution is not implied by a successful build. Official Bridge libraries and headers are never bundled. ViewWeave independently implements the mathematical mode rules after checking their meaning against official Looking Glass Unity Plugin 3.2.8; no vendor code is ported or bundled. Run `python3 tools/build_upm_distribution.py` after changing the source package to regenerate both self-contained distributions.

The verification project is `Tests/Metal/Unity`. `MacOSMetalValidationBuilder.Build` creates `.local/macos-validation/ViewWeaveMetal.app`; `Prepare` creates its Editor scene. The application rotates its sample geometry and records frame counters. R stops/restarts output, and Escape stops and exits. Generated scenes, Players, and detailed logs are verification artifacts rather than package content.

## Rendering and lifetime

Bridge supplies metadata and calibration, then its SDK is uninitialized. The display window and optical sampling are owned by ViewWeave. Unity renders/interlaces on Metal; a Unity render event copies the result into one private Metal texture. Unity producer completion schedules the presentation queue. Completion of ViewWeave's own consumer command buffer permits the next copy. Busy frames are dropped; no image is read back to the CPU during streaming. Teardown uses a one-pixel queue-tail readback to prove Unity completion before releasing the texture, together with native completion.

Stop immediately closes admission and hides the window. GPU retirement can continue afterward; `IsClosing` distinguishes this from full retirement. A new session waits for the previous session to retire. Pending event data and GPU callbacks retain their own session and textures. AppKit objects are released on the main thread. Screen disconnect, movement, or resolution changes stop output rather than continuing with stale pixel placement. Reconnect and start again after restoring the display arrangement.

The Windows `ViewWeaveBridgeSession` and D3D Worker remain Windows-specific. Metal preview and playback use dedicated controllers with shared Rig UI, source validation, and Editor producer/resource utilities. Shared, Metal and Windows responsibilities are described in [Platform boundaries](bridge-platform-architecture.md). The earlier finite `BridgeMetalExperimentalOutput` remains a separate diagnostic route. It must not share a process with this output after beginning its experiment; restart Unity between routes.

## Editor assertion when stopping Play

`Mismatched state in DefaultScenario, was Stopping but expected Idle` is a known Unity issue when script changes made during Play are recompiled on stopping. [UUM-154172](https://issuetracker.unity.com/issues/25291/mismatch-state-in-defaultscenario-error-is-thrown-when-exiting-play-mode-with-a-modified-script-and-recompile-after-finished-playing-enabled) lists 6000.6.4f1 as affected. Stop Play before changing source, then wait for imports and compilation to finish before starting again.

Unity's documented workaround is Unity Settings > General > Script Changes While Playing > `Recompile And Continue Playing`. This Editor preference affects other projects and allows recompilation during Play; change it only if that behavior is desired.

## Optical calculation and provenance

The interlace shader is an original implementation, not an import or port of the HoloPlay shader. It computes the lenticular phase for each RGB subpixel, selects a Quilt view, and samples that view. For a tableless mode-0 profile, `flipX=1` mirrors image X and reverses tilt and RGB direction. For a profile with cells, `flipX=1` reverses tilt only; it does not mirror display UVs or reorder RGB offset X values. RGB/BGR channel indices select the corresponding phase. `fringe` is only checked for finiteness and does not participate in correction. The calibration conversion follows the mathematical relationship in the Apache-2.0 [official WebXR configuration](https://github.com/Looking-Glass/looking-glass-webxr/blob/b44ed27fea197f28fbe4cb669bc350d141a9f8b1/src/LookingGlassConfig.ts); current mode and cell rules are documented in the [Bridge subpixel calibration note](bridge-subpixel-calibration.md):

`shaderPitch = rawPitch × screenWidth / dpi × cos(atan(1 / rawSlope))`

`tilt = screenHeight / (screenWidth × rawSlope)`; `RGB step = 1 / (3 × screenWidth)`.

The [Bridge native reference](https://lfdocs.lookingglassfactory.com/software/looking-glass-bridge-sdk/native-function-reference) and the installed runtime's public declarations provide the metadata ABI. Unity's [public native Metal interface](https://github.com/Unity-Technologies/NativeRenderingPlugin/blob/522254181faf188efa8b50c3e3bf6fce720b26e4/PluginSource/source/Unity/IUnityGraphicsMetal.h) supplies the producer command buffer. GPU/unit/build proof, screen capture, and physical optical acceptance are different evidence; see the [current calibration validation record](macos-unified-subpixel-validation-20261011.md) for the verified scope and limits.
