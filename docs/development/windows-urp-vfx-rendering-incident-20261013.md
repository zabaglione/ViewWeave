# Windows URP VFX rendering and Editor crash observation (2026-10-13)

This record captures a user-observed output mismatch and a later Unity Editor crash in the URP sample project. It is an incident record, not a controlled reproduction or a product compatibility result. The crash dump confirms an access violation during Unity shutdown, but neither the dump nor the available log establishes that VFX rendering or the budget guard caused it.

## User-observed behavior

The user reported that, in Play/Game view, the green lamps in `Multi-StripsGPUEvents` were visible while Looking Glass output stayed red. Three rotating coins from `RotationAngle.vfx` were visible on Looking Glass, but their periodic brightening seen in Game view was not reflected there; the user separately reported that the HDRP sample worked. These are user observations, not synchronized captures proving the same frame or settings on both displays. The supplied images show ordinary Game view content and do not prove Looking Glass output.

The user reported that Quarter output and Preview were smooth. In Play, after changing Output Quality from Preview to Balanced while `ViewRenderModeQuarter` was selected, the budget diagnostic appeared and the user later quit the Editor, which crashed. The configured history budget remained 4096 MB; the user did not report changing that budget. The diagnostic was captured in Play mode at frame 113, before rendering logical view 0: 0 of 12 requested views had completed; 12 history cameras were registered; the layout was 48 views at 480 x 360 per tile, with Temporal Anti-Aliasing. This is the state at the logged budget check, not proof that no earlier camera/history allocations or rendering occurred.

## Log and dump evidence

Only selected lines were preserved in the [portable safe log extract](../validation/windows-urp-vfx-rendering-incident-20261013/log-extract.txt); the full Editor log and crash dump were not copied into this repository. The Unity Editor log was from `UNITY_PROJECT_1/Logs/Editor.log`, 1175 lines, last written `2026-10-13T01:06:38.9876111Z`. The process was PID 106676. Unity 6000.6.4f1 had reached ready state before the shutdown. The dump was `Crash_2026-10-13_010639250/crash.dmp` and has SHA-256 `D71D829D04522D51CE3785A2590E84F2DCD61E3C32BF2981554581B99C3B2DFE` (695,017 bytes); it is not included here.

The logged error reports observed process graphics growth of 6083 displayed MB (MiB, bytes divided by 1,048,576), estimated texture growth of 54 MiB, and a configured budget of 4096 MB. Its raw counter values were baseline 3,533,831,142, previous sample 3,622,796,354, current sample 9,913,100,354, and high-water growth 6,379,269,212 bytes from baseline. The current-minus-previous sample is 6,290,304,000 bytes. The diagnostic says texture sampling was false for this call, and its reported texture peak was a high-water value. These graphics counters are process-global driver counters; they are not physical VRAM measurements or VFX-only allocations. The texture estimate covers observed RenderTexture objects, not just VFX-owned or planned quilt resources. Counter scopes differ, and peak values may come from different samples.

The D3D12 log reports skipped draws when `Hidden/VFX/MultiStripGPUEvents/Jacks/Jack Meshes` requested vertex SRV `attributeBuffer` index 0 and `Hidden/VFX/StripGPUEvent/Mushroom Cap/Mushroom Mesh` requested index 0 but neither binding was supplied. A separate CPU descriptor/source inventory—not the incident Editor log—maps the green quad path to index 4 and the Jacks and red-lamp output paths to indices 0 and 1. The user also described the Mushroom effect as visually incomplete but could not identify the missing element. The log does not identify whether these draws came from an ordinary Game camera or a quilt camera. This is evidence of missing bindings for those named draws; it does not establish that GPU event simulation failed, that the green quad is broken, that either warning belongs to a Looking Glass camera, or that these warnings explain the Looking Glass mismatch.

The crash dump analysis identifies exception `0xC0000005` (write) to address `0x11f0` at `Unity.dll+0x44383df`, on exception thread 60696. The project Editor log ends with `dup_nolock -> dup -> RedirectStdout -> Application::Terminate`, after Input System shutdown and `CodeReloadManager` destruction. This stack matches an earlier shutdown-crash signature by address and exception type, but the matching signature does not prove a shared root cause. The available evidence does not establish whether the budget exception, the earlier graphics growth, the VFX shader warnings, or another shutdown condition caused the crash.

## Focused paired-view probes

After inspecting the source and crash dump, three bounded Editor probe runs covered two graphs in an isolated clone with one normal camera and one quilt camera. They used AA and post-processing off, a single view, and unchanged original graph assets. These probes do not reproduce the user's TAA/PP-on, 12-view device output or Editor shutdown scenario.

The final 20-second `Multi-StripsGPUEvents` probe ran for 763 CSV samples. GPU-event-driven particles were generated: the green-light particle count became nonzero in 521 samples and reached 16; cable particles were nonzero in 701 samples. At the last sample, counts were Jacks 320, LightSoundOff 16, Cables 19,540, and Green 7. However, the strict green-color pixel gate (`G >= 45`, `G > R + 24`, `G > B + 24`) found zero qualifying pixels in both normal-camera and quilt-camera images, so NUnit reported one inconclusive case (not pass or fail); the Editor exited 2 with no residual process. This means the classifier did not detect pixels in that color range; it does not mean that the GPU event chain failed. The paired images show cable output in both camera paths. The first observed GreenLights-alive sample was frame 144, 8.73 seconds into the run. A prior 6-second probe ended before the GreenLights-alive observation and was inconclusive. The final run's missing-SRV warning count was zero. Its raw graphics counter delta was 4,181,760 bytes, private-bytes delta 44,240,896 bytes, history camera count returned to zero, and owned RenderTextures were released. This bounded result shows the GPU event chain can produce particles in this fixture; it does not settle whether the user's lamps appeared green on Looking Glass under the reported settings.

The `RotationAngle.vfx` probe passed one NUnit case and exited 0. It ran for 6.0109 seconds and captured 210 normal/quilt image pairs with three particles. Normal and quilt images differed by at most one pixel; sampled luminance was 104-108 and gold-channel range overlapped (4,034-8,831 versus 4,028-8,836). The inspected central view showed the coin highlight in both outputs. This was a one-view AA-off/post-processing-off Editor comparison, not a test of the user's Temporal Anti-Aliasing, 12-view quilt, or physical device brightness. It neither confirms nor disproves the reported Game-to-Looking-Glass periodic brightness difference.

Three earlier compile/setup attempts are retained separately in the evidence archive: two emitted NUnit setup failures and one compile attempt stopped without XML, all before VFX activation. They are not product failures and do not contribute passes. Across all six Unity launches, five NUnit cases were recorded: one bounded Coin pass, two setup failures, and two Green inconclusive results; the compile attempt without XML is outside that case count. The source asset hashes remained unchanged.

## Graph and pipeline inspection

Source inspection identifies `Multi-StripsGPUEvents` as GPU collision/event-driven behavior, not a C# VFX Output Events path. `RotationAngle.vfx` uses `VFXURPLitMeshOutput`, is opaque, and has `useEmissive=0`; its rotation and gradient setup can account for changing Game view appearance, but not the periodic-brightness difference reported between Game and Looking Glass. Specular reflection is one candidate explanation for periodic brightness, not a confirmed cause.

The existing scene-comparison pilots used `CollisionSimple` and `CollisionAdvanced`; they did not exercise these specific graphs or their missing-SRV paths. The paired-view probes above are separate targeted checks. The source also shows different submission paths: URP uses manual `Camera.Render()` while HDRP uses `StandardRequest`; normal URP `ScriptableRenderer` preparation paths are present. This is a code-path difference, not evidence that the submission path caused the observed output or crash. Swapping request methods would also change TAA/history semantics, so it cannot be treated as a single-variable fix without a controlled comparison.

## Scope and status

Three targeted Editor paired-view runs covered two VFX graphs, and no user project or SDK implementation was changed. The coin image-comparison case passed within its one-view AA-off fixture; two Green checks were inconclusive, although the longer run observed GPU event particle generation. Three separate earlier compile/setup attempts stopped before VFX activation and are not product failures. The Editor incident and Looking Glass image mismatch remain uncontrolled user reports; their cause is unresolved. The earlier bounded scene-comparison pilots remain limited to their own selected graphs and conditions and do not count as passes for this incident. No Player, general VFX compatibility, physical VRAM peak, or optical-quality result is claimed.
